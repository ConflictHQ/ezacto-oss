# Private CSV admission and preview

Refs #1181 and #1012. The Container implements private administrator staging
and immutable preview over the portable planner from #1180. This slice does not
confirm or apply time. `getCsvImportCapabilities` reports
`staging_supported: true` only on that Container, and `browser_ready: false` and
`apply_supported: false`. Worker discovery reports all three false; its private
CSV paths refuse before constructing database services or reading the body.

The canonical DTOs and operations are in
`packages/api/src/csv-import-staging-contract.ts`. Generated OpenAPI and client
methods use those definitions. The raw upload uses `application/octet-stream`
with `X-CSV-SHA256` and `X-CSV-Bytes`; it does not use multipart, JSON, base64,
a caller filename or a remote URL.

## Authority and storage

Every private operation requires a current administrator session; API tokens
are refused. Unsafe methods require exact same-origin CSRF. The route checks
current authority and run ownership before reading mapping JSON, upload bytes,
raw objects, diagnostics or catalog. Missing, another creator's and another
database incarnation's inputs all return `run_not_found`. Native session proof
is an internal session row id, never the cookie or bearer material.

The sidecar metadata database and generated raw objects live in the Container's
private data directory. Directories are mode 0700 and files 0600. There is no raw
download route, public object URL or user-controlled object path. Symlinked
objects/metadata are refused. Streamed upload bytes are limited to 5 MiB before
retaining an overflowing chunk, then checked against both the required SHA-256
and byte length. Mapping JSON is bounded to 1 MiB before parsing. Parser limits
remain 50,000 data rows, 40 source columns, 10,000 characters per field and 255
per name. Parsing and read-only planning run in a cancellable bounded work item,
with one work item per process, a time budget and a memory limit.

The destination incarnation is generated by migration 0165. Demo reset,
physical identity replacement and the supported offline restore quarantine
rotate it, so recycled numeric user ids cannot read an earlier incarnation's
private stage. Normal account closure and session changes are checked by the
live SQL session/role/closure fence.

## Explicit mapping and immutable preview

PATCH `/api/v1/csv-imports/:runId/mapping` is the explicit workspace registration
and choice action. It uses the existing singleton dataset ledger and current
session guard; preview itself never registers a source, writes setup, creates a
native import run or writes organization rows.

Choices state the workspace, frozen Clockify browser adapter, ISO date reading,
exporter IANA zone, source wall-clock interpretation, destination-rate pricing,
entity mappings and excluded physical lines. No browser/device zone, source
money, first-name candidate or destination currency is guessed.

A preview id binds the target, creator, file proof, choices, exclusions,
destination policy facts and imported-row history. Private full plans and facts
never appear in API DTOs. Refresh creates another immutable receipt when these
facts change; cursors bind the current preview and exact filter. The private
apply seam re-reads current facts before giving #1183 any input.

The paged mapping catalog carries opaque parent-scoped source keys, private
source labels and ancestor labels, exact destination ids, active/selectable
state and actual destination currencies. Excluded source entities remain
reviewable. None of these private labels are placed in diagnostic messages.

Tallies distinguish file rows, selected rows, new/already imported rows,
distinct rejected rows, diagnostic count, source seconds, destination seconds,
and their signed delta (which can include historical edits or tombstones).
`organization_currency` describes the organization; candidate currency describes
that destination. `unpriced: true` does not imply zero or USD.

## Diagnostics, retention and apply boundary

Structured diagnostics retain physical line, scope, static code/message and
invalid/unsupported/warning kind. File errors are not excludable. Warnings name
lost timing, ignored money/attachments and destination billable overrides
without copying a cell, email, note, filename or arbitrary parser message.
Diagnostic download is JSON rather than an executable spreadsheet. Status and
catalog are owner-only and cache-disabled.

Inputs have a visible 24-hour staging expiry. Explicit purge removes raw input,
mapping, full plans, private labels and row diagnostics while preserving only
minimal ids, file hashes, safe counts and native dedup/audit facts. The metadata
store uses secure deletion and DELETE journaling, so purged cells do not remain
in a live WAL. The expiry sweep also removes old orphan temporary
objects. Terminal retention uses the native finished time, never a delayed
callback's time; confirmed input also expires at its stated staging deadline, even after a
crash without a terminal callback. #1183 fences every native write at this input
expiry and uses retained metadata to reconcile active/pending jobs and verify
the exact current input association. Old superseded input must
never cancel a newer input for the same native dataset.

A private confirmation claim blocks concurrent purge and is replayable only
with the same command. This is an internal composition seam for #1183, not a
public confirm/apply operation or an enabled job runner. Status/cancel metadata
can remain available after raw input expires. A different administrator must
upload their own identical input and explicitly take over the native lease;
there is no transfer of another creator's raw file.

Native service/API tests use disposable organization databases, private files,
real session cookies and the actual read-only planner worker. They check
zero-write preview fingerprints, denial before reading content, object limits,
privacy and lifecycle behavior. Hosted adoption and Worker apply are outside
this Container-only slice.
